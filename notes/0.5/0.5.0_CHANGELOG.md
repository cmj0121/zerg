# Zerg 0.5.0 — release notes

The fifth release, and the one where the language **stops saying no** while a user writes a library.
0.4.0's sentence was _a spec is a value's type_: an `enum` can be generic, a method carries its own
type parameters, and a user can write an ABSTRACTION. This one is about the forms that used to refuse
them while they did.

> **0.4.0 let a user write a LIBRARY. 0.5.0 stops the language saying no while they write one.**

`Ord` derives. `Eq` and `Ord` reach a payload enum. `set[T]` is a type. A `struct` may contain itself
through a carrier. A callee may be an expression. A named argument, `nil` as a pattern, and a range as
a value. `in` asks the equality rule in its own words. A `spec` member is never `unsafe`.

It has finds this milestone made that were not on it, and they are named below rather than folded into
the sentence.

The short version is [`CHANGELOG.md`](../../CHANGELOG.md) at the repository root. This is the long one.

## How to read this

**Which compiler.** `make` builds two. `zerg0` is a Go-hosted seed whose only job is building the compiler;
`zerg` is that compiler, written in Zerg, and the one a build puts in `bin/`. **Every claim below is about
`zerg`.**

**The standing contract is unchanged.** A form is either lowered correctly or refused **by name** at compile
time, with a code and a place. Nothing new is silent.

## `Ord` derives, and `Eq` / `Ord` reach a payload enum

`spec Ord: Eq { fn less(o: This) -> bool }` is a built-in declaration, the third after `Eq` and
`Into[T]`. `<` `<=` `>` `>=` on a declared type ask that impl, the way `==` already asks `Eq`. One
method is required; the other three orderings are written out of it at the operator.

- **`#[derive(Ord)]` writes the lexicographic body** — field by field for a product, variant order for
  a sum — recursing into each field's own `<` the way the `Eq` derive recurses into its `==`.
- **`Eq` and `Ord` reach a payload enum.** A derive on one matches the tag **and** the payload on both
  sides at once: equality answers `false` where the tags differ, and the order answers by declaration
  order. `E9055` retires.
- **`E9054` narrows** to `Hash`, `Encode` and `Decode`. Those three stay `[not yet]`. Naming one at a
  `derive` is still that code. This release does not derive them.

## `set[T]` is a type

A unique-membership set — type, constructor, members. `E9064` retires.

- **`set([1, 2])` from a list**, and **`set()` where a type says what it holds**. Written where nothing
  says, `set()` is refused. A set has no literal: `{1}` cannot be told from a one-statement block.
- **What a set answers:** `x in s`, `s.len()`, `s.has(x)`, `for x in s` in insertion order, value
  semantics, and a rendering — `{1, 2}`, the members and not the pairs.
- **A set element is a map key here**, so what can be hashed is one question. This phase that question
  still answers `int` or `str`.

## A `struct` may contain itself through a carrier

`struct Node { pub next: Node? }` declares, builds, walks, renders and is released. So does a tree, and
so does a mutually recursive pair. The `nil` the carrier already carries is an end, and one pointer on
the cycle is a size.

**`E4026` narrows** to a cycle with no carrier. `struct Node { pub next: Node }` is still refused — it
has no size and nothing that can be absent, so there is no first value to build. Terminator-free
self-containment is not what was built.

## A callee may be an expression; a named argument, `nil` as a pattern, a range as a value

The forms `GRAMMAR` derived and this compiler refused, beside a call and a construction.

- **A callee may be an expression.** `fs[0](1)` calls the element. A lambda called where it is written
  calls the lambda. A function value in a field or a map calls through either. **`E9009` narrows** to
  the optional method call `p?.m(…)` and does not retire: `?.` answers an optional, so the call has to
  be conditional and its result an optional too. That is group 8's rule, not a callee's.
- **A named argument** in a call and a construction — `E9010` retires. A name picks a parameter in a
  call and a field in a construction, which is what lets a defaulted one in the middle be skipped.
- **`nil` as a pattern** — `E9068` retires. `nil` names an optional's absent side, and the arm beside
  it binds what the optional holds, which is what makes the pair exhaustive.
- **A range as a value.** `E9077` does not retire and **narrows**: a range is a value, and what is left
  under that number is a range of a type this compiler cannot compare.
- **`in` asks the equality rule in its own words.** The rule `in` asks **is** the equality rule, which
  is why the codes stay shared with `a == b` rather than doubled. What was wrong is the sentence: a
  program containing `x in xs` contains no `==`, and a message quoting one sent its reader through
  their own file looking for it. `E4038` says `in` now.

## A `spec` member is never `unsafe`

A leftover of 0.4.0, **closed this release**. `E9036` refused an `unsafe` `spec` signature as a form
this compiler had not built. It is not a form that gets built, so the number leaves `E9xxx`: `unsafe`
says who vouches, and a `spec` says what a method does. A requirement states the contract; how an
implementation keeps it is the implementation's business, discharged in the body and not announced in
the interface.

`E9036` **retires into a position**. These notes make no claim about an `unsafe` spec member as a gap.

## The finds this milestone made

All closed. None of them is the version's sentence.

- **[#178](https://github.com/cmj0121/zerg/issues/178)** — an owned rvalue field projection lost the
  temp. `S([1, 2], 7).n` built a struct, read a field out of it and walked away from the list. A
  binding registers a release at its declaration; a projected temporary has no binding. macOS has no
  LeakSanitizer, which is why this reached `main`.
- **[#181](https://github.com/cmj0121/zerg/issues/181)** — two gates reported a cause they had not
  established. `treesitter-check` swallowed the tool's output and said the grammar does not generate;
  `ci-fetch-testdata` said the fetch failed with credentials. Both keep the tool's own output now and
  say only what they saw.
- **[#183](https://github.com/cmj0121/zerg/issues/183)** — an `unsafe` method satisfying a safe spec
  requirement escaped through a box: safe code called it and printed its answer with no diagnostic
  anywhere. The position a `spec` member retires into is what closes that hole, from the
  implementation's end as well as from the requirement's.
- **[#182](https://github.com/cmj0121/zerg/issues/182)** — `unsafe` is one concept — the group — and a
  `ptr` cannot leave it. There is no `unsafe fn` and no `unsafe` in a type. The dangerous operations
  are unsafe-only, and the dangerous values cannot leave the context those operations live in.
- **[#167](https://github.com/cmj0121/zerg/issues/167)** — a 0.4.0 leftover in the **release
  machinery**, not a language subject of this release. `SHA256SUMS` named one tarball of three:
  three runners each wrote a file of that name, and merging the directories kept whichever was
  written last. The published file covers every tarball now.

## What is still not built, and what is left over

The rows are in [`docs/surface/grammar.md`](../../docs/surface/grammar.md) § _What is specified and not
built_, each with the code that refuses it, and `make chapter-codes` fails if a row outlives its form.
What this release narrowed rather than retired in that table is `p?.m(…)` and a range of a type this
compiler cannot compare. `Hash`, `Encode` and `Decode` at a `derive` stay `[not yet]` in
[`docs/core/derive.md`](../../docs/core/derive.md) — naming one is `E9054`.

Two tickets 0.4.0 named as leftovers of its own subject still fail, re-measured on the shipping
compiler at this branch point. Both are loud — a program is refused, not miscompiled — and both are
named here rather than fixed, because a criterion that rewards silence is worse than one that ships a
known defect:

- **[#165](https://github.com/cmj0121/zerg/issues/165)** — GitHub closed the ticket on the 0.4.0 notes
  merge that _named_ it as leftover; there was no fix. The two diagnostics still disagree. `Nothing`
  is `E3079` write `Maybe[int].Nothing`. That spelling is `E3069` undefined name `Maybe`.
  `Maybe.Nothing` is accepted. Closing the ticket did not make them agree.
- **[#166](https://github.com/cmj0121/zerg/issues/166)** — still a generic method's receiver polluting
  a later solve, but the observed program has shifted. `b.wrap(9)` into `unwrap_or(m: Maybe[int], …)`
  is `E3038` `Maybe[int]` versus `Maybe[Bag]`, plus a cascade `E3026` wrap takes 1 gives 2. Declaring
  `fn wrap[U]` without calling it, then `Maybe.Nothing`, is accepted. The ticket said the wrap _call_
  succeeded and a later `Maybe.Nothing` was solved to the receiver. That is no longer the observed
  program.

**62 gates**, up from 60. The two new names are `formula` and `release-sums`.

## Still no compatibility promise

The surface moves, and a `[not yet]` becoming built is the ordinary way it will move. Nothing here is a
stability commitment; the standing contract is about **truthfulness**, not about permanence.
