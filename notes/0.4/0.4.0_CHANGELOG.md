# Zerg 0.4.0 — release notes

The fourth release, and the one where the type system grows into something you can write a **library** with.
0.3.0's sentence was _the grammar stops being a promise_: the forms `GRAMMAR` derived were built rather than
refused. This one is about what a user can then SAY with them.

> **0.3.0 let a user write generic DATA. 0.4.0 lets them write an ABSTRACTION.**

A `spec` is a value's type. An `enum` can be generic. A method can carry its own type parameters. A parameter
can say _any destination_ instead of naming one, and a user can write their own `Option`.

It has a second subject, and it is the same one 0.3.0 discovered: **a claim that is remembered is not a claim
that is checked.** 0.3.0 audited what the gates assert; this release audits how many times they say it, and
collecting ten copies of two doctrines into one each is what found four gates that could not see what they
were written to see.

The short version is [`CHANGELOG.md`](../../CHANGELOG.md) at the repository root. This is the long one.

## How to read this

**Which compiler.** `make` builds two. `zerg0` is a Go-hosted seed whose only job is building the compiler;
`zerg` is that compiler, written in Zerg, and the one a build puts in `bin/`. **Every claim below is about
`zerg`.**

**The standing contract is unchanged.** A form is either lowered correctly or refused **by name** at compile
time, with a code and a place. Nothing new is silent.

## A `spec` is a value's type

A `spec` was a bound and nothing else: you could write `fn f[T: Display](x: T)` and could not write
`fn f(x: Display)`. The second is what a library wants — `log`'s `Sink` is the acceptance test, and it is
written the way it wanted to be now.

- **A spec-typed position builds a BOX**: a counted cell carrying the value and a witness table, one table
  per `impl S for T` and per `(spec, arguments)` pair. A call on a box dispatches through it.
- **The box is an ordinary owned value.** It is copied, given back and released like every other one, and its
  payload is given back with it — the two `fix(runtime)` and `fix(emit)` commits under that sentence are the
  difference between a feature and a leak.
- **`is` works on a box**, and a member answering `This` comes back as the spec rather than as the concrete
  type it happened to be.
- **A box renders.** The witness table carries the rendering, so `print` on a spec-typed value says what the
  value says — `E9116` retires.
- **A parameterized spec is a type too** (`Into[int]` in a parameter), with the members seated under the
  applied key — `E9115` retires.
- **What a box cannot do is named.** A generic member cannot dispatch through one, and a binary same-type
  member is refused on one, because neither has an answer a witness table can hold.

## An `enum` can be generic, and a method carries its own parameters

- **A generic `enum`** declares, instantiates and matches — `E9003` retires. A variant's parameters are
  solved from the payload, supplied at the application, or refused by name when neither reaches them, which
  is the rule that makes `Option[T]` a thing a user writes rather than a thing the language owes them.
- **A method carries its own type parameters**, joining the monomorphization key — `E9044` retires.
- **`E9048` retires**: a `spec` names a type.

## The doctrine is provided once, not restated

Four ledgers — the programs the seed cannot build, the corpus cases that report under the sanitizers, the
cases `zerg` cannot build yet, and the make targets that are not gates — each wrote out for itself what
holding such a list means. Six loops ran a program and compared, and each decided for itself how many of
stdout, stderr and the exit status to look at.

Each doctrine is one implementation now: [`scripts/lib/ledger.sh`](../../scripts/lib/ledger.sh) is UNLISTED,
STALE and MOVED, with the `?` qualifier one list had invented and the scope another had;
[`scripts/lib/runcmp.sh`](../../scripts/lib/runcmp.sh) is the three answers of a run, compared as files
rather than through `$(...)`, which strips a trailing newline from both sides at once.

**What collecting the copies found:**

- **`gates-check` had two clauses that could report and not fail.** Its `$fail` check sat in the middle of
  the script and there was none at the end, so the clause about a gate reading the private corpus and the
  clause about a gate declaring a floor wrote their findings to stderr and exited 0 — in the script whose
  whole subject is a gate that cannot fail.
- **Two sites threw stderr away.** `install-check` ran the program the INSTALLED compiler built with
  `2>/dev/null`, and `release-tarball` did the same to the probe whose stdout becomes the name of every
  published artifact. They are the only two places in this repository that ask what an installed toolchain
  produces.
- **`behaviour-check` never asked the exit status**, and merged the two streams into one file before
  comparing them against the recorded stdout.
- **The board named `install-check` as tolerating an absent corpus**, which it does not read — the stale line
  a list with no second direction can never be asked about.
- **The corpus skip list checked an exit status.** A skipped case was required to fail and any failure would
  do, so one that stopped parsing read as one still waiting for its feature. Each line names the **code** now.

## The dead-code questions nobody asked

Three had no gate. Two of them are about this repository rather than about a program, and so had nowhere to
be asked at all — `make dead-code` asks both, with a floor under each:

- **A `pub` function of the compiler that nothing in the compiler calls.** `L102` is about a private
  function, deliberately: a public name is a module's interface, and a library's interface answers to callers
  outside the tree. The compiler is not a library. **The stdlib is the carve-out**, and it is written down.
- **A script nothing invokes.** `gates-check` asks whether every TARGET is on the board and cannot see a file
  that is not a target at all. The hand tools are a ledger with a reason each.

The third was `L101`, and the defect was the **rule** rather than the reach. An `import` binds a namespace in
the FILE that writes it — neither transitive nor shared with the file's neighbours, which is what `E5007`
says out loud — and the rule was asking whether ANY file of the merged program reached through it. So an
import one file wrote and never used read as used whenever a SIBLING in the same module wrote the name. Three
lines in this compiler were dead that way, with `make lint` green over all three.

## The fixes a release carries

- **A map method released a receiver it had borrowed** — a 0.3.0 segfault.
- **The last two renderers, and a slice, gave back what they concatenated.** Ownership had been decided one
  level too low.
- **`#[derive(From)]` died on a built-in payload**, and an `impl` may now sit on a built-in when the spec is
  this program's.
- **A call does not construct a spec**, and inference no longer answers one.

## What is still not built, and what is left over

The rows are in [`docs/surface/grammar.md`](../../docs/surface/grammar.md) § _What is specified and not
built_, each with the code that refuses it, and `make chapter-codes` fails if a row outlives its form.

Two tickets found by 0.3.0 ship unfixed, which is the milestone's own rule for a leftover — they are finds
from the previous release, not subjects of this one:

- **[#123](https://github.com/cmj0121/zerg/issues/123)** — an `unsafe fn` as a `spec` requirement is `E9036`,
  and what an implementer owes for one has no written rule. Reading it as a safe signature is the silent
  option, and it is refused for that reason. **These notes make no claim about an `unsafe` spec member.**
- **[#127](https://github.com/cmj0121/zerg/issues/127)** — `zerg fmt` does not order a run of bindings
  `const`, then `mut`, then immutable.

**60 gates**, up from 58.

## Still no compatibility promise

The surface moves, and a `[not yet]` becoming built is the ordinary way it will move. Nothing here is a
stability commitment; the standing contract is about **truthfulness**, not about permanence.
