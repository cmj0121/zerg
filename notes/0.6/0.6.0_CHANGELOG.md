# Zerg 0.6.0 — release notes

The sixth release, and the one where the **tools say what the compiler says**. 0.5.0's sentence was
that the language stops saying no while a user writes a library. This one is about the two commands
that stand between that user and the compiler: `zerg lsp`, which answers in their editor, and
`zerg doc`, which answers for the source they read.

> **0.5.0 stopped the language saying no. 0.6.0 makes the tools say what the compiler says.**

A keystroke reports what `zerg build --emit check` would report, about the program the buffer is in,
at the place the compiler named. A name at the cursor has a declaration, and hover is that
declaration's document. The documentation that lives in the source is the only copy: `zerg doc --check`
runs its examples, a marker separates the reader's text from the maintainer's, a prefix finds a
declaration from the terminal, and the HTML pages are a rendering of the same extraction.

It has finds this milestone made that were not on it, and they are named below rather than folded into
the sentence.

The short version is [`CHANGELOG.md`](../../CHANGELOG.md) at the repository root. This is the long one.

## How to read this

**Which compiler.** `make` builds two. `zerg0` is a Go-hosted seed whose only job is building the compiler;
`zerg` is that compiler, written in Zerg, and the one a build puts in `bin/`. **Every claim below is about
`zerg`.**

**The standing contract is unchanged.** A form is either lowered correctly or refused **by name** at compile
time, with a code and a place. Nothing new is silent.

## The language server says what the compiler says

`zerg lsp` publishes the check's own findings. It does no resolution and no checking of its own: every
answer below comes out of the walk `zerg build --emit check` runs.

- **An abort is published where it points.** A refusal that ends in the compiler's `--> file:line:col`
  line is drawn at that place, not at the top of the file
  ([#191](https://github.com/cmj0121/zerg/issues/191)). One raised inside a `#[derive]` expansion is
  drawn at the decorator that wrote the expansion, with the code and sentence the check prints
  ([#203](https://github.com/cmj0121/zerg/issues/203)).
- **Every open buffer is the program.** An unsaved buffer stands in for its file in every program that
  contains it, and a change, a save or a close re-publishes every open buffer whose program contains
  that file. An unsaved signature change in `lib.zg` now reaches the open `main.zg`
  ([#193](https://github.com/cmj0121/zerg/issues/193)).
- **A name has a declaration.** `textDocument/definition` and `textDocument/references` answer from one
  name index the checking walk builds while it resolves each name. A use a generic body resolves
  differently per instantiation answers with every declaration it may be
  ([#24](https://github.com/cmj0121/zerg/issues/24)).
- **Hover is the document.** It prints what `zerg doc` prints for the declaration under the cursor,
  from `zerg doc`'s own extraction — there is no second reader of a comment
  ([#192](https://github.com/cmj0121/zerg/issues/192)).
- **The outline is a view of the program.** A struct's fields and an enum's variants are its children,
  a range is the whole construct and its selection the name, and a finding underlines the construct the
  compiler named. A buffer that will not parse answers `RequestFailed` with the compiler's sentence
  instead of an empty outline ([#25](https://github.com/cmj0121/zerg/issues/25)).
- **A check is one walk.** Diagnostics and lint come out of one lowering walk, where they used to take
  two ([#22](https://github.com/cmj0121/zerg/issues/22)). A quick fix is looked up from that walk's
  notes rather than paid for with a second walk per menu
  ([#204](https://github.com/cmj0121/zerg/issues/204)).
- **A long session stays in the band of one check.** The memory a session retained was in the C the
  compiler emits: several shapes never gave back a value they owned. Each is fixed where the value is
  produced, and some of them were use-after-frees on `main`, not only leaks
  ([#23](https://github.com/cmj0121/zerg/issues/23)).

`make lsp` holds each of these to the compiler: the buffers agree with `zerg build --emit check`, a check
is one walk, and a long session stays in the band of one check. The server is also a Claude Code plugin
(`zerg-lsp`); [`docs/tooling/lsp.md`](../../docs/tooling/lsp.md) says how to install it and what it
costs.

## `zerg doc`: the source is the only copy

- **The fences are run by the command.** `zerg doc --check` builds and runs every ` ```zerg `
  example in a comment. One with an ` ```output ` fence under it is compared line by line, and one
  without must run and print nothing. The five-module allowlist in a second reader is gone
  ([#17](https://github.com/cmj0121/zerg/issues/17)).
- **`##` is the reader's text, `#` the maintainer's.** The page, `--brief`, the index, `--check` and a
  hover read the `##` lines. `zerg doc --all` is the maintainer's page, every comment as written. The
  standard library is migrated, and every exposed declaration still carries reader text
  ([#18](https://github.com/cmj0121/zerg/issues/18)).
- **Find a declaration by name.** `zerg doc -s <term>` lists the exposed declarations whose name begins
  with the term, through the same extraction the page uses
  ([#19](https://github.com/cmj0121/zerg/issues/19)).
- **Static HTML.** `zerg doc --html <dir>` writes a page per module, an index and an offline search. No
  font, framework or CDN. The pages are a second rendering of the one extraction, and the search's
  matching rule — the one rule stated twice, in JavaScript — is held to `-s`'s answers by a gate
  ([#20](https://github.com/cmj0121/zerg/issues/20)).
- **The rest of the tree teaches the fence.** `fmt.md`'s examples, the nvim syntax file and the
  standard library's `cli` example are the `##` fence now, and `editor-align` holds the syntax file to
  the fence the runner reads ([#243](https://github.com/cmj0121/zerg/issues/243)).

## The leftovers this release closed

Finds from 0.4.0 and 0.5.0 that the milestone took on. All closed.

- **[#166](https://github.com/cmj0121/zerg/issues/166)** — named as a leftover by 0.5.0. The diagnosis
  was wrong: a generic fn that never names `this` is an **associated** fn, and the generic path put the
  receiver in front of its arguments anyway. Generic fns now follow the rule plain fns follow: `x.f(…)`
  on one is `E3152`, and `Bag.wrap(9)` builds.
- **[#195](https://github.com/cmj0121/zerg/issues/195)** — a bare variant is its file's, not the
  program's. A variant declared anywhere took over a bare name in a file that cannot see it. The same
  rule now holds wherever a name is lowered away from the file that wrote it: a parameter default, a
  field default and a decorator's expansion resolve in their own file.
- **[#197](https://github.com/cmj0121/zerg/issues/197)** — a default sees no caller binding. A caller's
  local of the same name answered a default's names, **silently**: a wrong value printed. A default that
  names an earlier parameter reads that argument.
- **[#214](https://github.com/cmj0121/zerg/issues/214)** — a call through a module takes that module's
  defaults, parameters and signature. With two imported functions of one name, `bb.g(1)` took `aa`'s
  default — also a **silent** wrong answer.
- **[#198](https://github.com/cmj0121/zerg/issues/198)** — `E3151` gives the reason that applies: a spec
  member and a rendering override are methods whatever their body reads, and no longer send the reader
  looking for a `this` nobody wrote.
- **[#199](https://github.com/cmj0121/zerg/issues/199)** — an associated fn of a generic type is reached
  through the type (`Box.make(3)`), and a template's declared types are checked for undeclared names.
- **[#200](https://github.com/cmj0121/zerg/issues/200)** — an associated fn named through its type
  without a call, `Bag.wrap`, is a value, the same as a free fn named without a call. `E4089` fires only
  when the type declares neither a constant nor a fn of that name.
- **[#201](https://github.com/cmj0121/zerg/issues/201)** — two files may each declare a private type of
  the same name. The reader never sees the name the compiler tells them apart by.
- **[#202](https://github.com/cmj0121/zerg/issues/202)** — a provided spec member inherited by an impl in
  another module is that impl's member, not an inherent impl in the spec's file.
- **[#206](https://github.com/cmj0121/zerg/issues/206)** — a private enum is not nameable from another
  module, qualified or bare. The value forms built on `main`; they are `E5008` now, the code the type
  position already gave.
- **[#205](https://github.com/cmj0121/zerg/issues/205)** — whether a package is the standard library
  depends on which directory it is, not how its path was typed. A project's own `stdlib/` no longer
  takes the standard library's identities under `zerg test` or `zerg doc --check`.

## The finds this milestone made

All closed. None of them is the version's sentence.

- **[#237](https://github.com/cmj0121/zerg/issues/237)** — a re-raised message some binding owns was
  freed on the way to the guard, so `raise m` of a caught error's text came back empty. The compiler
  re-raises its own refusals that way, so the language server took a refused program as finished and
  published it **clean**. The message is the Err's own now, in both compilers, and the server treats a
  raise as an abort whatever its text.
- **[#238](https://github.com/cmj0121/zerg/issues/238)** — `zerg lint` dropped what the compiler's walk
  found, and a program the compiler refuses linted clean and exited 0. It prints the check's lines now,
  and exits 1.
- **[#239](https://github.com/cmj0121/zerg/issues/239)** — `L402` told the author to make a `mut fn` a
  plain `fn` when its only write was a call to another `mut fn` through `this` — advice the compiler
  then refused with `E3023`.
- **[#240](https://github.com/cmj0121/zerg/issues/240)** and
  **[#241](https://github.com/cmj0121/zerg/issues/241)** — `L102` counts an associated fn named as a
  value as a use, and judges a private function in its own file rather than by its name across the
  program.
- **[#242](https://github.com/cmj0121/zerg/issues/242)** — `zerg desugar` changed what an f-string
  printed: `{{` and `}}` were copied into the plain string doubled, and the `{` of a `\u{…}` escape was
  read as a hole.
- **[#260](https://github.com/cmj0121/zerg/issues/260)** — a select could read a channel's values out of
  the order they were sent, under several workers: a **silent** wrong answer, seen once on CI as
  `conc_for_select` printing `12 1 4`. A select scans a channel and pushes its waiter under two different
  holds of the lock, and a sender that filled the buffer in between left the waiter beside older values;
  the next sender handed its own value past them. A sender now hands a waiting receiver the oldest value
  and queues its own. `TestConcurrencyStress` summed what it read, which no order changes, so a runtime
  test now reads one stream in order.

## What is still not built, and what is left over

What 0.6.0 put out of scope stays out: `zerg doc --serve`
([#21](https://github.com/cmj0121/zerg/issues/21), blocked on networking), completion, signature help,
workspace symbol and rename ([#194](https://github.com/cmj0121/zerg/issues/194), which reads this
release's index), and the package layer ([#60](https://github.com/cmj0121/zerg/issues/60)). `Hash`,
`Encode` and `Decode` at a `derive` stay `[not yet]` — naming one is `E9054`.

Re-measured on the shipping compiler at this branch point. Each is loud — a program is refused or a
finding reported, never miscompiled — and each is named here rather than fixed:

- **[#165](https://github.com/cmj0121/zerg/issues/165)** — closed, and still not fixed; 0.5.0 said the
  same. A bare `Nothing` is `E3079` write `Maybe[int].Nothing`. That spelling is `E3069` undefined name
  `Maybe`. `Maybe.Nothing` is accepted. A reader who follows the first diagnostic still arrives at the
  second.
- **A white-box suite linted alone is refused.** `zerg lint src/compiler/zerg/parser_test.zg` is
  `E4016`: a suite calls its module's private functions unqualified, so as a file on its own it is a
  program the compiler refuses. `zerg test` builds it as its package; `zerg lint` does not yet. The
  compiler's two white-box suites are left out of `make lint` for that reason.
- **An Err never releases its message.** Retaining the message is the fix for #237, and the leak is its
  price: every heap message a program raises is held until exit. The sanitizer ledger names it, beside
  the leak `assert_claim` already had.

And one that is a reading of the code rather than a measurement:
**[#261](https://github.com/cmj0121/zerg/issues/261)** — a plain send or receive reads its waiter's `done`
flag without the channel lock after a park, and a wake token a select leaves standing can end that park
early. By the reading, a value handed across in that window could be overwritten. A stress aimed at it
did not reproduce it, so it is filed rather than changed.

**63 gates**, up from 62. The new name is `compiler-test`, the compiler library's own suites with a floor
under them.

## Still no compatibility promise

The surface moves, and a `[not yet]` becoming built is the ordinary way it will move. Nothing here is a
stability commitment; the standing contract is about **truthfulness**, not about permanence.
