# Zerg 格式化器與檢查器規則

`zerg fmt` 與 `zerg lint` 套用的每一條規則，以及指名它的代碼。屬於
[語言參考](../language.zh-TW.md)的一部分。亦有 [English](fmt.md)。

每條規則都有**代碼**，讓它可以被指名——在診斷裡、在 review 裡、在把它關掉的命令列上。前綴用來
分組，做法與 Python 的 linter 相同；分組的依據是**規則做什麼**，而不是哪一個 pass 實作它。

| 前綴   | 分組   | 是什麼                               |
| ------ | ------ | ------------------------------------ |
| `F1xx` | 版面   | 在哪裡斷行、縮排多深                 |
| `F2xx` | 間距   | 兩個 token 之間放不放空白            |
| `F3xx` | trivia | 人為了人而寫下的東西會發生什麼事     |
| `F4xx` | 改寫   | 會**移動**程式碼、而不只是排版的規則 |
| `L1xx` | 死碼   | 寫下來但沒有任何東西到得了的東西     |

## `zerg fmt`

```sh
zerg fmt <file.zg>...              # 就地重寫；印出它改動過的檔案
zerg fmt --off F401 <file.zg>...   # 放過某一條規則（可重複）
```

格式化器從 **token** 出發，不從 AST。這正是整個設計決定：AST 已經丟掉了讀者放進去的註解與空行，
而一個會吃掉這些東西的格式化器，沒有人會跑第二次。

它**依構造而冪等**——輸出由「輸入本身會產生的同一串 token」建出，所以對已格式化的原始碼再格式化
不會有任何改變。

### F1xx — 版面

| 代碼   | 規則                                        |
| ------ | ------------------------------------------- |
| `F101` | 每層縮排一個 tab；`}` 收在它展開時的那一層  |
| `F102` | 一行一個敘述——lexer 插入的 `;` **就是**斷行 |
| `F103` | 換行的運算式，每多一層括號就多縮排一層      |
| `F104` | 連續空行只留一行，群組內也是                |
| `F105` | 跨行的括號群組，收尾自成一行                |

`F105` 就是讓換行的鏈式有一個看得見的結尾：

```zerg
a := (
 builder()
 .run()
 .fast()
)
```

而不是一個要讀者去數的 `))`。它適用於任何「收尾比展開晚一行」的 `(` 或 `[`，所以換行的引數列表
也會得到同樣的形狀。

`F103` 數的是括號而不是敘述，所以巢狀的群組每多一層括號就多縮一層，每個收尾都落在自己的開頭底下：

```zerg
x := sum(
 sum(
  1,
  2
 ),
 3
)
```

改以敘述為基準的話，一個巢狀裡的每個收尾都會擠在同一欄，讀者分不出誰關誰——而且內層的收尾會跑到
它所關內容的**左邊**。

多行鏈式外面的括號不是裝飾，是**它能被解析的原因**：`)` 之後的斷行會結束該敘述（見
[`GRAMMAR`](../../GRAMMAR) 的 ASI 規則），而未關閉的 `(` 內不會插入 `;`，所以括號正是把整條鏈綁在一起的東西。

### F2xx — 間距

| 代碼   | 規則                                                          |
| ------ | ------------------------------------------------------------- |
| `F201` | 二元運算子兩側、逗號之後、`=>` 兩側各一個空白                 |
| `F202` | `(` `[` 之後、`)` `]` `,` 之前、名稱與它的 `(` 之間，都不空白 |

### F3xx — trivia

| 代碼   | 規則                                               |
| ------ | -------------------------------------------------- |
| `F301` | 註解保留原文，自成一行或跟在它原本跟隨的程式碼之後 |

### 註解裡的範例

註解裡的程式碼範例以 **doctest 提示符**標記——`>>>` 起一個頂層項目，`...` 接續它：

```zerg
# Example — greeting someone:
#
# >>> fn main() {
# ...     print greet("world")
# ... }
#
# and it prints:
#
#     hello, world
```

`F301` 原封不動保留這一切；提示符是慣例，格式化器不從中讀出任何意義。哪一行用哪個提示符同樣
是撰寫慣例——兩者都表示「這一行接下來是 Zerg」。

標記是**明確的**，而這是關鍵決定。註解裡有兩種縮排區塊：原始碼，以及程式**印出來**的樣本。
單靠版面推斷會把後者當成前者染色——在 `cli` 自己的檔頭，一段貼上的 help 畫面會讓 `Options:`
變成欄位名、`--output` 變成運算子、`VALUE` 變成型別。錯的高亮比沒有高亮更糟，所以由作者說明
哪個是哪個。

用提示符而不是 `圍欄，是因為註解將來要產生文件，而那個產生器輸出的是 markdown——
也就是說` 是**輸出**的語法。把輸入也拼成同一個樣子，會讓「必須把一種原樣傳遞、同時產生
另一種」的產生器，光看形狀分辨不出兩者。

### F4xx — 改寫

| 代碼   | 規則                                               | 預設 |
| ------ | -------------------------------------------------- | ---- |
| `F401` | 只含一個跳轉的 if 區塊，收成它本來就是的後綴 guard | 啟用 |
| `F402` | import 分組——標準函式庫在前、其餘在後，各組字母序  | 啟用 |
| `F403` | 引數列表要嘛一行，要嘛一個元素一行——不會各半       | 啟用 |
| `F404` | 兩個以上的 import 收成一個括號 group               | 啟用 |
| `F406` | 在必要處加空行：guard 段、宣告段、引導區塊的註解   | 啟用 |

`GRAMMAR` 把 `return x if c`、`break if c`、`continue if c` **定義為** `if c { … }` 包住同一個
跳轉的糖——一個後綴 `if`，三種跳轉。兩種寫法說的是同一件事，而其中一個用四行說。格式化器選短的
那個——那正是 guard clause 的用途：例外的出口不再打斷它所守護的那段程式的形狀。裸的提早返回也
一樣：`return if c`。

「優先使用糖」是這裡的通則，不是為 `return` 開的特例：**只要語言為「已經寫下的東西」提供了更短
的表面形式，標準形就是短的那個**，讀者也就不必再去注意兩者是同一件事。

要注意這個後綴 `if` **不是**什麼：它掛在跳轉上，不掛在運算式上——Zerg 沒有 `A if X else B`。
條件**運算式**是區塊形式，而且 `else` 是強制的：`x := if c { 1 } else { 2 }`。

```zerg
fn clamp(n: int) -> int {          fn clamp(n: int) -> int {
 if n < 0 {                             return 0 if n < 0
  return 0                   →       return 9 if n > 9
 }
 if n > 9 {                             return n
  return 9                       }
 }
 return n
}
```

它只改寫**不會弄丟任何東西**的情況，其餘一律不動：

- 區塊內恰好一個敘述，而且是跳轉；
- 沒有 `else`——else 帶著第二個分支，guard 形式承載不了；
- 內部任何地方都沒有註解，因為註解是人放進去的，而這個 pass 沒有地方把它放回去。

`F402` 是 Go 的慣例，理由也相同：import 清單被**讀**的次數遠多於被改，而分組且排序過的清單，
讓「這個檔案有沒有用到 X」用看的就知道，不必逐行掃。標準函式庫排在前面，因為那是讀者已經
知道的部分；其餘則是這個程式自己帶進來的。

什麼算標準函式庫，是那組固定的隨附模組。模組以路徑的**最後一段**解析，所以 `import "std/io"`
會和 `import "io"` 分在同一組。

它只改寫一連串單純的 `import "path"`，一旦其中出現別的東西就放棄——註解（它屬於它所在的那個
import，排序會讓它變成孤兒），或 `import pub`（它的 re-export 是作者選定的順序）。

接著 `F404` 把這串收進 `GRAMMAR` 給 `import` 的括號形式，一行一個 spec，而 `F402` 的那個空行
會活著進去，在裡面當同樣的分隔：

```zerg
import "cli"          import (
import "zerg"    →        "cli"
import "io"               "io"

                          "zerg"
                      )
```

那裡的排序是 `F402` 的，括號是 `F404` 的。兩者一起呈現，因為那才是 `zerg fmt` 印出來的東西——
中間那個狀態沒有人看得到。

**只有一個 import 就不動它。** 這是 gofmt 的答案，理由也是 gofmt 的：group 的用途是把一份清單
綁在一起，而只有一個元素的清單，就是那個敘述本身加上兩行儀式。

和 `F402` 不同，`F404` 會把 `pub` 與 `as` 一起收進去——那兩者正是 `F402` 放棄的原因，因為
`F402` 會**重新排序**，而這條規則不把任何東西移到別的東西前面：

```zerg
import (
 "io"
 pub "util/text"
 "a/text" as at
)
```

只要 import 之間有註解就放棄，理由同 `F401`；已經是 group 的那一串則原封不動。而在整串**之後**
的註解屬於下一個宣告，所以它只是讓這一串結束，不會讓規則放棄。

寫得出這個形式，也正好找出 self-hosted parser 讀不回它：group 被吃掉、一個路徑都沒回傳，於是
一個用 group 匯入的檔案交給 driver 的是**空的** import 清單——而失敗會在好幾個階段之後，以一個
未知的型別名冒出來，不是在那個沒被讀到的 import 上。

`F105` 說的是「群組已經跨行之後，收尾該放哪」；`F403` 說的是「已經跨行的群組長什麼樣」。
**作者放得下一行的，就留在一行**——這條規則從不去拆一個原本沒被拆開的群組。

作者**確實**拆開過的群組，會被併回一行，除非以下任一條否決：

- 攤平成一行後，它會結束在第 80 欄或更後面——一個 tab 算 4 欄；
- 它有 6 個或更多頂層元素。

只要有一條否決，群組就改為在**每一個**頂層逗號斷開。不會各半：一個只圍著其中一個元素斷行的
群組，以前會把其餘的印在收尾後面，留下一條掛在尾巴上的 `), 3`，那兩種形狀都不是。

```zerg
x := sum(                        # 之前
 1,
 2,
)
y := sum(sum(
 1,
 2,
), 3)

x := sum(1, 2)                   # 之後
y := sum(sum(1, 2), 3)
```

寬度才是真正的判準，而數量是給寬度看不見的情況留的保險：六個引數不論多短，都是一份要用掃的
清單，而不是一行要用讀的程式。

兩條門檻都**不會下令**斷行，這是刻意的。這個 pass 一次只看到一個群組，而不是整行，所以跨過第
80 欄的是那行**最後**一個群組，而不是值得斷開的那個——在 `return 0 if a or b or c(x, y)` 裡
那是 `c`，它的兩個引數會被攤成三行，而真正讓這行變長、又沒有括號可斷的那個條件，卻原封不動。

**沒有頂層逗號**的群組兩條都豁免。鏈式與括號包住的運算式，斷在它們的作者斷的地方——那些斷行說
的是「步驟在哪裡」，而不是「這行放不下了」。它們得到的是「開頭自成一行」，於是每個步驟都從
同一欄開始：

```zerg
n := (
 builder()
 .run()
)
```

和 `F401` 一樣，只要內部任何地方有註解就整組放棄：註解是人放進去的，而把行併起來沒有地方把它
放回去。

**尾隨逗號一律拿掉**，併行或斷行都一樣。在一行上它只是一個後面什麼都沒有的逗號；而在多行上，
多行的參數列表正是文法唯一**不接受**尾隨逗號的地方，若在簽名拿掉、在呼叫保留，同一種形狀就會
有兩種寫法。

`F405` 是 `F401` 的原則套用在字串上：只要語言為「已經寫下的東西」提供了更短的表面形式，標準形
就是短的那個。

```zerg
"n=" + s + " of " + t                    →   f"n={s} of {t}"
"v=" + strconv.to_string(n, 10) + "!"    →   f"v={n}!"
```

格式化器沒有型別，而這裡也不需要。`+` 從來不是異質的——emitter 只在左運算元是 `str` 時才把它降到
字串串接——所以**一條鏈裡任何一個字串字面值，就決定了整條鏈的型別**。那就是觸發條件。

`strconv.to_string(X, 10)` 收成 `{X}`，因為 base 10 本來就是 hole 的呈現方式。其他 base 保留原本
的呼叫：hole 沒有辦法表達它。

這條規則主要是繞著**優先級**這個陷阱建起來的。`+` 和 `-`、`|`、`^`、`+%`、`-%` 同一個優先級，所以
`"a" + b - c` 解析成 `("a" + b) - c`，那條 `+` 鏈**不是**整段 token——改寫整段會讓運算式重新結合。
因此運算元之間允許出現什麼是一份白名單，而上面那五個只要出現在鏈自己的深度就結束它。

它在以下情況放棄：少於三個運算元；沒有字面值；沒有 hole；鏈跨越一行以上；raw、三引號或帶
`\u{…}` 的字面值；hole 裡帶著 `"`、`\`、`{`、`}`；字面值裡帶大括號——雙寫是正確的但比原本更難讀；
以及 `out = out + …` 這種累積，那裡的 hole 會讓累積器和被內插的值長得一模一樣。

`F406` 會**寫入**一個空行，而做這件事的門檻是刻意訂高的：整棵樹的函式 body 內總共只有**十個**
空行，而 `fmt.zg` 自己 1300 行一個也沒有。所以這條規則只在兩個地方放，而且兩個都是這裡的作者
本來就會放的地方。

**超過一個** guard 組成的一段，後面接一個空行：

```zerg
fn conv_ty(s: str) -> Ty {        fn conv_ty(s: str) -> Ty {
 return TInt if s == "int"         return TInt if s == "int"
 return TStr if s == "str"    →    return TStr if s == "str"
 return TNil
}                                     return TNil
                                  }
```

一個 guard 是它所守護的那一行的一部分；兩個以上是一張**出口表**，而一張表需要邊界——兩邊都要，
所以從函式中途開始的一段，前面也會加一個空行；在 body 的開頭，`{` 本身就是那個邊界。這份克制
就是這條規則的大部分：這棵樹的 218 段 guard 裡有 182 段只有一個 guard，一個都不會被動到。

**三個以上的連續宣告**若從區塊中途開始，前面加一個空行，後面不加：

```zerg
fn c_index(mut &em: Emitter, target: Expr, idx: Expr, sb: Subst) -> str {
 em.used_rt = true

 ct := c_type(c_list_elem(c_infer(em, target)))
 tgt := c_expr(em, target, sb)
 ix := c_expr(em, idx, sb)
```

和 guard 之間的不對稱是結構性的。一段 guard 是**終端的**——後面沒有東西消費它，所以它讀起來像
一張表，兩邊都要邊界。一段宣告是**前言**：這棵樹的 167 段裡有 106 段後面接著 `for`，而那個迴圈
引用了它們宣告的每一個名字；其中 86 段的最後一個宣告，就是下一行 `for` 的迴圈變數。在那裡加空行
會把 `i = 0` 和 `i < n` 拆開。它沒有遠端的邊界，因為它還沒被讀完。

是三個不是兩個——兩個宣告是一對，不是一個段落，這和這條規則說「一個 guard 是它所守護的那一行的
一部分」是同一步。

**自成一行**、而且前後都有程式碼的註解，前面會加一個空行。註解放在那裡是為了帶出一個新的段落
——那正是它自成一行而不是跟在程式碼後面的原因——而這棵樹 body 內既有的空行有一半正是這個形狀。
它適用於任何區塊，所以 `struct` 裡有註解的欄位群，會得到和 Go 一樣的分隔。

它在五種情況放棄：一段 guard 前面的註解，那是這段的**標題**——空行加在註解前面，不加在註解與它
所引介的那張表之間；頂層的註解，那是宣告的註解，宣告之間的間距是作者的；換行引數列表裡的註解，
它屬於它所在的那個元素，加空行反而把它和它在講的東西分開；後面只剩一個 `}` 的註解，它沒有帶出
任何東西；以及那裡已經有一個空行。

它刻意**不做**的是在巢狀區塊的 `}` 之後加空行。那在這棵樹裡是 683 個位置——那不是一條關於可讀性
的規則，而是把整棵樹重寫一遍。

### 哪些規則可以關掉

`F1xx`–`F3xx` 沒有商量餘地：它們就是「標準形」的定義，而一個為它們提供選項的格式化器，會變成
兩個人設定成兩種樣子的格式化器。`F4xx` 改的是程式碼的**形狀**而不是它的間距，所以 `--off` 是
為它而存在。`F105` 放在版面而不是改寫，因為它只決定一個既有 token 去哪裡；`F403` 歸在改寫，理由
剛好相反——它會插入沒有人寫過的斷行，也會拿掉併行後的清單不再需要的那個 token；而 `F406` 寫的是
一整行沒有人寫過的東西。

## `zerg lint`

```sh
zerg lint <file.zg>...   # 印出發現；有發現時以非零值結束
```

每一項檢查都只從解析後的檔案回答——沒有型別、沒有流程分析——這讓它對自己能主張什麼保持誠實。
發現依原始碼順序回傳，而非零的 exit code 讓 `zerg lint` 可以當作閘門，而不只是裝飾。

### L1xx — 死碼

| 代碼   | 發現                 | 為什麼值得印一行                                                         |
| ------ | -------------------- | ------------------------------------------------------------------------ |
| `L101` | 未使用的 import      | 該模組被讀取、解析、併入程式卻毫無用處，還對下一位讀者謊報這個檔案的依賴 |
| `L102` | 從未被呼叫的私有函式 | 公開的是模組的介面；私有而無呼叫者的，就只是死碼                         |
| `L103` | 從未被讀取的 binding | 那個值是為了沒有人而計算的                                               |

```text
L101 unused import "strconv"
L102 private function `never` is never called
L103 binding `unused` in `main` is never read
```

`L102` 永遠不會報 `main`：不管原始碼怎麼說，runtime 都會呼叫它。

## 新增一條規則
