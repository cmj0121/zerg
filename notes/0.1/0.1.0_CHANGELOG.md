# Zerg 0.1.0 — release notes

**2026-08-05.** 1308 commits, 2026-04-22 to 2026-08-05. The first release, and therefore the first entry with
nothing to compare itself against: everything below is new, and what the sections are really doing is saying what
exists and — as carefully — what does not.

The short version of this document is [`CHANGELOG.md`](../../CHANGELOG.md) at the repository root. This is the
long one, broken out by area.

## How to read this

**Which compiler.** `make` builds two. `zerg0` is a Go-hosted seed whose only job is building the compiler; `zerg`
is that compiler, written in Zerg, and the one a build puts in `bin/`. **Every claim below is about `zerg`.** The
seed's narrower subset is its own contract, in [`src/bootstrap/README.md`](../../src/bootstrap/README.md), and a
reader writing Zerg never meets it.

**The standing contract.** A form is either lowered correctly or refused **by name** at compile time. It is never
a crash, never a silently wrong answer, and never an error reported by `cc` or the linker against generated code
nobody wrote. This is why the "known limitations" section below can be a list rather than a warning: each entry
is a sentence the compiler will say to you.

It is also the first release in which that contract was **measured** rather than asserted — about four hundred
probes compiled and run against `bin/zerg`, one per normative claim in the specification. Where the contract
holds, the limitations below are the sentences the compiler says. Where it does not, the breach is in **Known
deviations**, and the specification marks it in the chapter it belongs to. A contract nothing measures is a wish.

**The markers.** The specification states the intended language and marks each gap — `[not yet]`,
`[deviation]`, `[implementation-defined]`, with silence meaning "this works". The vocabulary is defined in
[Conformance](../../docs/conformance.md), which is also where the diagnostics contract and the runtime-abort
contract live.

**How the capability claims here were arrived at.** Every "this works" and every "this does not" below was
compiled and run against `bin/zerg` on 2026-08-05, rather than copied from prose. That is not ceremony: the
README's own status section had gone stale in both directions by the time this release was cut, and a release
note that inherits a stale claim propagates it with a version number attached.

## Language & grammar

[`GRAMMAR`](../../GRAMMAR) at the repository root is the normative definition of the syntax, in W3C-style EBNF,
built up in twelve groups from `nop` to `unsafe`; the prose companion is [Grammar](../../docs/surface/grammar.md).

**Declarations and types.** `struct` (product), `enum` (sum, with payloads, recursion, and discriminants a
program can read with `int(v)` and reverse with `E.of(n)`), tuples with `.0` / `.1`, and `type X = Y` as a
**strong typedef** — a name with an identity of its own, not a transparent alias, so `Celsius` and `int` are two
types. The primitive scalars are `bool`, `byte`, `rune`, `int`, `uint`, `float`, `str` and `nil`; `uint` is a
real type rather than a spelling of `int`, which is what makes `int + uint` a compile error and `>>` arithmetic
on the signed and logical on the unsigned. A `rune` is the one scalar whose bound is a **predicate** rather than
a range — the code points minus the UTF-16 surrogates — which is also why it is not a width in the fixed-width
ladder.

**Values meeting types.** Two distinctions carry the type system. **Adoption** is what an untyped literal does
when it lands in a typed position; **widening** is what a value that already has a type does, and only the first
happens on its own. The second is `Into`: a one-step implicit conversion at a typed position, specified as a
matrix over the scalars and implemented as a **hub at `int`** — two clauses, not seven rows — and openable for
a type of your own with `impl Into[T] for S`. A **typed position** is where a value meets a declared type; there
are fourteen of them, and the release closes all fourteen through one funnel that requires the slot's name, so a
value cannot reach a declared type without the rule seeing it.

**Errors are three questions, three spellings.** `e is X` asks identity, `e in X` asks membership in X's subtree
— the built-in kinds form a **tree**, and a taxonomy link is an IS-A, not a WAS-CAUSED-BY — and `e.unwrap()`
asks what it was raised from. `in`'s right side is always a set, which is what lets one operator serve an error
kind, a list and a map. Both **operators** are built, and so are the `Error` interface's `message()` and
`unwrap()`: an error carries a message and a cause, and a program can now read them rather than only
classify what it caught.

**Control flow and the value tier.** `if` / `for` / `for in` / `match` with exhaustiveness checking and arm
guards, `break` / `continue` acting only on the nearest loop with no labels, the postfix forms `return … if c`,
`break if c`, `continue if c` and `raise … if c`, `guard { … }` yielding a `Result[T]`, `raise … from …` with
the cause recorded, `defer` (at the enclosing block's exit, on every path, arguments captured by value), and
`del`. `Either[X, Y]` is nameable, `Result[T]` is the case whose right side is
an `Err`, and both survive in a signature.

**Optionals.** `T?` is a real type with a carrier of its own, and all four operators: `?` `??` `?.` `!`. `??` is
right-associative as the grammar always said; `?.` flattens when the field is itself optional, because `T??` is
not a writable type.

**Concurrency.** `spawn`, `chan[T]` with an optional capacity, the directional annotations `<-chan[T]` and
`chan[T]<-`, `close` as a statement, `select` with a non-blocking `_` arm, and `for select`, which is the form
that **ends** — one ready arm per round, finishing when every watched receive channel has, with no terminal arm
and no counter. A receive answers `T?`: the stream ending is an **absence**, the producer dying is a **failure**
raised with that producer's own `Err`. `chan[T?]` is refused, because `nil` would otherwise mean both. `for v in
ch` iterates a channel directly — which is why the language has no `yield` and no generator type: a producer
coroutine sending to a channel is the generator, and the send is the yield.

**Arithmetic.** `+`, `-`, `*` and unary `-` raise `OverflowError`; `+%`, `-%`, `*%` and unary `-%` wrap. `/` and
`%` are Euclidean, so the remainder is never negative and `a % n` is a valid index for either sign; a zero
divisor raises `DivideByZeroError`, and a shift at or beyond the operand's width raises. `//` is that same
division spelled so the **result's type** is what decides: `a // b` is an `int` whatever the operands are, so
`7.5 // 2.0` is 3 with no round trip.

**Text.** f-strings, `str` concatenation and content comparison, `list[byte](s)` and `list[rune](s)` to decode,
`str(bytes)` / `str(runes)` to build one back with UTF-8 validated (no NUL, no surrogate, no overlong, at most
U+10FFFF, `EncodingError` otherwise), and `for c in s` over the runes. A `str` is not indexable, deliberately.

**Modules.** `import "name"` and `import "path/to/dir"`, import groups, `import pub` re-export, `pub` on a
declaration, a typed module-level `const` that is one object across every unit that reads it, and `init()`,
which runs once before `main`.

**Generics.** `fn f[T: Eq](…)` monomorphizes. Type arguments are **solved from the call** structurally, so
`assert_eq(1, 1)` needs no `[int]`; a type parameter no argument mentions is refused rather than guessed; and a
bound is checked at the instantiation, where there is a concrete type to check it against.

**Decorators.** `#[derive(Eq)]` writes the `impl` from the structure — generated **as source and parsed**, so it
cannot drift from what a hand-written `impl Eq for P` parses to. `Eq` is the sole source of `==` on a struct or
an enum, derived or written by hand.

## Compiler

The shipping compiler is ~20k lines of Zerg in [`src/compiler/`](../../src/compiler), GPL-3.0-or-later.

**It compiles itself.** `make build` runs the whole chain: the Go seed builds an intermediate, and the
intermediate builds the compiler that ships — **so the seed is off the delivery path**. `make fixpoint` checks
that stage1 and stage2 emit byte-identical C, which is the difference between self-hosting as a claim and
self-hosting as a description.

**Front end.** A hand-written lexer and recursive-descent parser over the whole grammar, with f-strings as one
token desugared in the parser into the `+` chain they are defined to be, so nothing downstream knows they exist.

**Diagnostics, in two halves — and only one of them arrived.** A **checked rule** reports the full treatment:
`error:`, then `--> file:line:col`, then the source line with a caret under what the message concerns. It is
also **not the only one you get** — findings are collected and the walk carries on, which is safe because the C
built after a finding is thrown away before `cc` is invoked. Positions come from a marker statement the parser
leaves before each statement rather than a span on all forty-nine AST variants; the file rides on the function
declaration. `#line` hands the same position downstream to `cc`, a debugger and a profiler. The lexer has
diagnostics of its own, `E101`–`E108`, reported the moment a file is read.

A **refusal** reports none of it. The parser and the emitter turn a form away through `raise`, which prints one
bare line and exits — no file, no line, no caret, and no second finding. Those are **170 of the compiler's 235
reporting sites**, and 80 of the 170 are the `NotImplemented` refusals. The two halves side by side:

```text
$ zerg build p.zg               # a rule the compiler CHECKS
error: undefined name `nope`
  --> p.zg:2:2
   |
 2 |     print nope
   |           ^

$ zerg build box.zg             # a form the compiler has NOT BUILT
NotImplemented: a generic struct `Box[…]` — this compiler erases type parameters, and a field names one
```

**The boundary moved during this release, and in the right direction.** Three rules that had been bare `raise`
sites gained a place: `undefined name`, a struct built without a field it requires, and a conversion that cannot
read a number out of a string. All three are rules about programs the **language** rejects rather than forms the
compiler has not built, which is why they belonged on the checked side all along — the position was live where
they raised, and only the migration was missing. That is 173 → 170, and `undefined name` — the error a beginner
meets first — is off the list.

What remains is not all one job. The emitter's refusals can be migrated the same way, one at a time. The
parser's cannot: **`parser.zg` has no diagnostic channel at all** — zero references to `Diag` — so a refusal
there cannot carry a place until one is built. That is why the fuzz gate's two `expect` cases are named as owed
rather than absorbed into a ceiling: they are the shape of the work, not the residue of it. The specification
marks the split as a `[deviation]` in [Conformance](../../docs/conformance.md), and it is repeated under Known
deviations below.

**Checking.** Type inference is bidirectional. On top of it, `src/compiler/zerg/check.zg` holds the rules an
ill-formed program breaks — mutability, one binding per block, `bool` conditions, operand types, the slots a
value enters, a call's argument count, `spec` satisfaction, duplicate declarations, `match` exhaustiveness — and
`make reject` pins 159 programs the compiler turns away itself. Type equality is **structural** over the type
enum rather than a comparison of diagnostic spellings, and `TUnknown` equals nothing, including itself.

**A `spec` requires a signature, not a name.** Satisfaction compares arity and, at each position, the
parameter's name, its type, its `mut &`-ness and whether it has a default, plus the return type — because
positional calls exist, so order is contract. It is decided over the **whole program** rather than out of a
cache, because a cache that decides legality gives one source two answers.

**Code generation** lowers the checked AST to C. Declarations are emitted in dependency order computed as a
graph, not by a fixed sequence of passes; a cycle is named as one. Generic instantiation is **AST-to-AST
substitution**, so a specialization arrives at the checker, the emitter, the mangler and the copy/drop rules as
an ordinary function — the same move `derive` makes. Erasure was rejected: it would need a uniform boxed value
this language does not have, because a `list[int]` is int64s and not pointers. The mangling invariant is enforced
rather than remembered — `cc` runs with `-fno-dollars-in-identifiers`.

**The driver.** A program is grouped into **units** (a module is one file, or the several files of a directory
module); each unit becomes its own object and one link puts them together. Results are cached by the C a unit
emitted — which already folds in its source, everything it sees and the compiler that produced it — in
`.zerg-cache/`, and `-j` builds several units at once. On the machine that landed it, building the compiler with
itself measured 1.28s at `-j1`, 0.56s at `-j4`, and 0.33s when nothing had changed.

**The install story.** A source file is a module until something asks it to be a program, and what asks is
`fn main` — so `zerg build main.zg` links an executable and `zerg build lib.zg` produces an object, without a
flag. The compiler finds its own root from its own path, probed rather than assumed, so it works outside the
source tree; `make install PREFIX=…` lays that layout out.

## Runtime

~5.7k lines of C in [`src/runtime/`](../../src/runtime), MIT — the floor that reaches the OS through the
platform C library and nothing else.

**Scheduler.** M workers, N stackful coroutines, one shared run queue; a coroutine that parks on one worker may
resume on another. What that buys is the only thing it should: two runnable coroutines can occupy two CPUs. A
program's output does not depend on it, and at M = 1 it is exactly the cooperative single-worker scheduler.
Threads sit behind a shim with three implementations — pthread, win32, and `thread_none.c`, the last of which is
not a stub but the semantics the other two must match at M = 1. `ZRT_SEED` makes a single-worker run a pure
function of program and seed.

**Channels** are refcounted with holder and sender counts; the direction that decides a spawn's contribution is
the callee parameter's, so a spawned consumer does not count as a sender and the channel closes when it should.
A program ends when `main` does, and a deadlock aborts with a kind rather than hanging.

**Memory is scope-owned, with no tracing GC.** Values are freed at scope exit in reverse order on every path,
including the abort unwind, over a `setjmp`/`longjmp` cleanup stack; recursive types and strings are
reference-counted. `list[T]` is a by-value header over a heap buffer with **copy-on-write** behind an atomic
refcount — the invariant that makes it sound is that a header is never shared, only the buffer — and `map[K, V]`
is an insertion-ordered hash reusing the same value semantics. **Two names of a value type never alias**,
including through a struct that holds a list.

**An emitted program gives back what it owns.** The shipping emitter had cut memory management on purpose, on
the argument that a self-hosting compiler is a batch tool — but this is the backend every Zerg program is built
with, and a long-running one would leak every string it formatted. A release is now registered where the binding
is declared and given back by unwinding to a mark, which is the exit every path already goes through. The
concurrency corpus went from 39 leak reports to 0 with LeakSanitizer's `detect_leaks` on.

**Abort.** An uncaught error writes `Kind: message` to standard error, runs the pending `defer`s on the unwound
path, and exits 1. The kinds are a fixed taxonomy, one runtime type with a kind tag — which is what makes
`e is ValueError` a comparison rather than a cast.

**Sanitizers.** The runtime tells AddressSanitizer where the stack went. `zrt_ctx_swap` moves the machine to a
stack ASan has not been told about, and with use-after-return detection on, an instrumented frame lives in a
per-thread fake-stack arena that a worker unmaps when it stands down — so a waiter parked on a live channel
became a hole in the address space. The fiber API closes it, and the gate now **asks** for the option rather
than inheriting a default that differed between a laptop and CI. ThreadSanitizer builds and runs but is
deliberately not a gate: the park protocol has a coroutine take a channel lock and the scheduler release it, on
one OS thread, which pthreads allows and TSan's fibers-as-threads model cannot express.

## Standard library

~2.2k lines of **pure Zerg** in [`src/stdlib/`](../../src/stdlib), MIT. Logic lives in `.zg`; only the
irreducible syscall and hardware leaves are in the C runtime, bridged by intrinsics. `math.sqrt` is a Zerg
algorithm and `io.read_file` loops a syscall leaf — neither is a libc or libm binding. The full catalogue with
signatures is [Standard Library](../../docs/runtime/stdlib.md).

| Module    | Provides                                                                    |
| --------- | --------------------------------------------------------------------------- |
| `io`      | stdout / stderr writers, `write_int`, whole-file and stdin read, file write |
| `fs`      | `exists`, `remove`                                                          |
| `os`      | `env`, `exit`, `platform`, `arch`, `run`                                    |
| `strings` | search, `split` / `join`, trim, case folding, count / replace / fields      |
| `ascii`   | ctype-style byte classification, for a tokeniser                            |
| `cli`     | the declarative command line, and the `--help` it renders                   |
| `strconv` | base-2..36 `parse_int` / `to_string`, `parse_bool`                          |
| `time`    | `now`, `monotonic`, and the `after` / `ticker` timers                       |
| `math`    | `abs` / `min` / `max`, `sqrt` / `pow`, the rounding family, `pi` / `e`      |
| `rand`    | a deterministic, non-cryptographic generator                                |
| `atomic`  | the safe shared-mutable primitive — **not importable by `zerg`**, see below |
| `testing` | `assert` / `assert_eq` / `assert_ne`                                        |

`cli` is worth singling out: a program **declares** its arguments, its sub-commands and the function each one
runs, and that declaration is the only description of the command line that exists. The parser reads it, the help
renderer reads it, the validator reads it. There is no second copy to fall behind — `zerg`'s own command line is
declared with it.

Eleven of the twelve import cleanly. `import "atomic"` does not: `Atomic[T]` is a generic struct, and a generic
struct is one of the forms this compiler refuses — so the module ships and cannot yet be used.

## Tooling & gates

**One binary, three jobs.** `zerg build`, `zerg fmt`, `zerg lint`, because there are three jobs; `tokens`, `ast`
and `c` are `--emit` stages rather than commands saying the same thing twice. `zerg --version` reports the number
in [`VERSION`](../../VERSION), and so does `zerg0`.

**`zerg fmt`** prints from the token stream, so comments survive, and it is proven to emit byte-identical C. Its
rules have codes, grouped by what the rule does rather than by which pass implements it: **F1xx–F3xx are what
"canonical" means and cannot be switched off; only F4xx — the rules that move code — can**, with
`zerg fmt --off F401`. It **refuses what it cannot read**, gated on bracket balance rather than a parse, because
a formatter has to work on source this compiler cannot yet compile. See [fmt](../../docs/tooling/fmt.md) for the
full rule list.

**`zerg lint`** reports unused imports, dead private declarations, the null-safety group `L2xx`, and `L5xx`, the
first rule that needed types — answered by recording findings during the lowering walk rather than giving the
linter a second copy of inference.

**The gates.** `make` targets, each pinning something a green build would otherwise not imply:

| Gate                 | What it holds                                                                      |
| -------------------- | ---------------------------------------------------------------------------------- |
| `build` / `fixpoint` | the chain builds, and stage1 and stage2 emit byte-identical C                      |
| `version-check`      | `VERSION`, the generated source, and both compilers agree                          |
| `examples`           | all 25 examples are built by `zerg` **and run**; the list is a glob, not names     |
| `corpus`             | 80 of 88 conformance programs pass; a `conc_` case runs ten times, not once        |
| `oracle`             | 62 programs agree between the seed and the shipping compiler, on stdout and status |
| `refuse`             | 141 unbuilt forms are refused **by name**, none left to `cc`                       |
| `reject`             | 159 ill-formed programs are turned away by the compiler, with a position           |
| `reject-fuzz`        | the corpus's working programs, broken, still meet the standing contract            |
| `fmt-corpus`         | a case states a formatting rule by being `fmt`'s fixpoint                          |
| `fmt-tokens`         | formatting changes spacing and not the token stream                                |
| `fmt-self`           | the compiler's and the stdlib's own 23 sources are already canonical               |
| `lint`/`lint-check`  | the tree is clean, **and** every lint rule still fires                             |
| `sanitize-conc`      | the concurrency corpus under ASan/LSan, in both worker modes, ten runs each        |
| `docs-links`         | every docs path the repo cites resolves — including the ones in source comments    |
| `linux-ci`           | the Linux gates in a container, because two Linux-only defects were invisible here |

Two of these exist because a gate that measures nothing looks exactly like a gate that finds nothing. The
oracle's **skipped set is a contract**: 39 programs the seed cannot build, each accounted for by the seed's own
sentence, in two inventories because a case name is private-corpus content. And CI's corpus fetch is
**required** when the token is present — a `continue-on-error` step had been reporting success while its outcome
stayed failure, so `make corpus` and `make sanitize-conc` had never once run in a job that went green.

**One of them used to be green because it routed around the problem, and what it was routing around was a
defect.** `make examples` built two demos with **`zerg0`** — the seed — because `zerg` could not build them:
`examples/modules` used a named argument and `examples/1g/init` a module-level inferred binding. So two shipped
examples were provable only by the compiler the README tells a reader they never meet, and a reader who typed
the `zerg build …` line in the example's own header got a `NotImplemented`. Both are now written in the
language this compiler has, and the seed is off that target.

Underneath the second one was a wrong answer rather than a missing form. The entry unit takes the whole
program's **constants** and its own file's **`init()` calls**, so under separate compilation an imported
module's `init()` was emitted, prototyped in every unit, and called from nowhere: `import "m"` where m
declares an `init()` did not run it, and the program printed the rest of its output as though it had. The
seed's single translation unit makes the entry file and the whole program the same `File`, which is exactly
why a gate pointed at the seed could not see it — a gate aimed at the narrower compiler is a gate agreeing
with itself.

The example list is also a **glob** now. `examples/1g/private` was in neither loop, so nothing built it: a
negative example asserting a refusal this compiler does not make, sitting green in the tree because the gate's
list was written by hand. 20 examples were built by this target before, two by the seed; 25 are now, all by
`zerg`.

**CI** runs per-PR on Ubuntu and macOS. macOS ASan has no LeakSanitizer, so the leak signal is a Linux one.

## Documentation & licensing

The specification is 46 Markdown files under [`docs/`](../../docs), organised by what a reader is trying to do
— core, code, surface, runtime, tooling — with `language.md` and `conformance.md` on top, and paired
English / `zh-TW` throughout. The English text is authoritative; the translations carry no independent normative
weight. `GRAMMAR` is normative for syntax, the chapters for semantics, and notes on how the bootstrap lowers Zerg
to C are informative.

**Zerg is licensed in layers, on one question: does this code end up inside the binary you ship?** The runtime,
the standard library, the examples, the scripts and the editor integration are MIT, so a program written in Zerg
can be shipped however you like. The compiler is GPL-3.0-or-later, which reaches a modified toolchain and not its
output. The specification and `GRAMMAR` are CC-BY-SA-4.0. What no license grants is the name. See
[`LICENSE`](../../LICENSE).

## Known limitations

Each of these is **refused by name** at compile time: the compiler says the form's name and stops, so a program
that uses one never reaches `cc` and never runs wrong. The list is the union of what the specification marks
`[not yet]` and what a probe of the shipping compiler confirms; the two forms that are accepted and then dropped
rather than named are in **Known deviations** below, where they belong.

**Generics.** A generic `struct` or `enum` (this compiler erases type parameters, and a field or a payload names
one); a generic **method** (its specializations would each need a name in its type's namespace); a bound naming
more than one spec, `T: A + B`; a generic `type` alias; and an **explicit** type argument at a call — `id[int](7)`
is refused, and inference is how a type argument is supplied.

**Traits and derive.** `derive` on a payload enum (`Eq` is derived for a fieldless enum, whose variants differ
exactly as their discriminants do — write `impl Eq for V` with a `match`); `Ord`, `Hash`, `Encode` and `Decode`;
a `spec` member with a **body**, so a provided method must be written in each `impl`; `spec` as a type.

**Values and patterns.** `set[T]`; a fixed-size array `[T; N]`; `==` on a `list` or a `map`, since a container
has no declaration to derive it on; tuple, struct and list patterns in a `match` arm; or-patterns (`1 | 2 =>` —
write consecutive integers as the range `1..=2`, which the formatter will do for you); a destructuring binding
`(a, b) := e`; a block used as an expression, and so as a `match` arm body; a nested `{ … }` block as a
statement, because every binding has the enclosing function's scope.

**Calls and closures.** A **named argument** at a call — arguments bind by position, so a struct is built
`P(1, 2)` and not `P(x: 1, y: 2)`; a closure that **captures** anything beyond its own parameters; a call through
a function value held in a container, and an optional method call `p?.m(…)`.

**Errors and resources.** `code()` on an `Err` answers absent and always will until a user-defined error type
exists to carry one — `message()` and `unwrap()` read the message and the `from` cause, and `opt.ok_or(err)`
and `res.ok()` convert between the two carriers. And `with … as` for a scoped resource, which `defer` covers
in the meantime.

**Text and rendering.** The f-string conversions `!r` / `!s` / `!a`, the `:spec` format spec, and the
self-documenting `{x=}`; structural rendering of a composite, so a struct or a `list[byte]` has no automatic
`Display` — render its fields.

**Memory and the unsafe layer.** `Ref[T]` and `deref`, and with them the `atomic` module, which is written as a
generic struct; command literals, because what the expression is worth is a stdlib question the grammar leaves
open; `unsafe`, raw pointers (`addr`, `ptr`) and inline assembly.

**Other.** The `is` type-test for a non-error type; the `Reader` I/O surface (`io.read_stdin` exists and returns
the bytes); and the `zerg test` runner, which the seed minimization removed and which has not been rebuilt in
Zerg.

## Known deviations

A deviation is a program that compiles and behaves differently from what the specification says — a bug with a
fix owed, not a documented state. Each is marked where it appears in the spec.

The five that are **silent** — the program compiles and the answer is wrong — come first, because they are the
ones a reader cannot discover by being careful:

- **A `str` literal `match` arm never fires.** `match s { "y" => 1  "n" => 0  _ => -1 }` answers `-1` for
  `"y"`. The arm lowers to a POINTER comparison while `"y" == "y"` in the same file lowers to `strcmp`, so
  one construct compares strings and the other compares addresses, with no diagnostic from either.
- **An if-expression does not check that its branches agree on a type.** `if false { 1 } else { 2.5 }` is
  `2` — the float truncated into the int the first arm settled on. `match` checks the same rule and says so,
  which is what makes this an omission in one construct rather than a decision.
- **`~` on a `byte` yields the unmasked 64-bit complement** unless the result lands in a `byte` slot:
  `print ~b` for `b = 12` is 18446744073709551603 where 243 is specified.
- **`main`'s `Result[nil]` is discarded**, so a `Right` returned from `main` prints nothing and exits 0 — the
  one path a program has for expected failure reports success.
- **A module-level inferred binding is dropped** rather than refused (below, in its own entry).

Two more break the contract in the other direction, by not being a Zerg diagnostic at all:

- **`in` and `??` used as a whole condition reach `cc`.** They lower to a GNU statement expression emitted
  inside the parentheses `if` and `while` already own, so `if 2 in xs { … }` fails as
  `error: expected expression` against generated C. It reaches `if`, `for`, and the postfix `return … if`,
  `break if`, `continue if` and `raise … if`; binding the expression to a name first compiles, which is why
  it looks intermittent. A program with no `fn main` fails in the linker for the same reason — nothing
  refuses it first.
- **Deep nesting crashes the compiler.** Around 800 levels of nested parentheses, list literals or calls
  exhausts the parser's stack: `SIGSEGV`, no diagnostic, no depth limit.

And the structural ones:

- **A refusal carries no position.** `file:line:col`, the source line and the caret are on the rules `zerg`
  **checks** and absent from the forms it **refuses** — a `NotImplemented` from the parser or the emitter names
  the form and stops there. 170 of 235 reporting sites are on that side, 80 of them `NotImplemented`. This is
  the deviation with the widest reach, and the one visibly moving: three rules crossed to the checked side in
  this release, `undefined name` among them.
- **Module visibility is not enforced.** A module can call another module's private function. `pub` is parsed,
  and re-export works; what is missing is the refusal.
- **Top-level constants initialize in source order**, not dependency order, so a constant whose initializer
  reads one declared after it reads that constant's zero value; a cycle among them is not diagnosed at all.
- **`init()` is eager, not lazy.** Every `init()` runs before `main`'s first statement rather than at the
  first use of the module that owns it, so one in a module a run never touches still runs.
- **Two declarations are accepted and then dropped**, so the name goes missing instead of the form being named:
  a module-level inferred binding `answer := compute()` (the typed `pub const N: int = 5` is the module constant
  that works), and a mutable global inside a module-level `unsafe { … }` group. Both compile the declaration and
  then report `undefined name` at the use site. That message now carries a caret, which makes the defect sharper
  rather than softer: the caret points confidently at a correct line, and the wrong one — the declaration is
  where the compiler gave up, and it says nothing there.
- **The C99 fallback is asked for, not discovered.** The emitted C is compiled as **C17**, which is the
  dialect the specification names, and `ZERG_CSTD` selects `c99` or `c11` for a build that needs one — CI
  compiles and runs both. What is `[not yet]` is the automatic retreat: nothing probes whether a `cc` can
  do C17. Until this release the flag said `c11` in every invocation while the front page said C17, and
  no gate compared the two; the fallback had never been compiled at all, and did not.
- **Left-to-right evaluation order** of call arguments and operator operands is not enforced; the spec's
  intended order is `[not yet]`, and the current order is implementation-defined in practice.
- **The scheduler is cooperative, not preemptive.** Nothing takes a coroutine off its worker until it parks, so
  a CPU-bound coroutine occupies one, and as many of them as there are workers stop the program.
- **A hardware fault the runtime cannot intercept** — a coroutine stack overflowing past its guard page, or
  `main`'s unguarded native stack — terminates by signal without running `defer`s, rather than as a clean
  `StackOverflowError`.
- **A receiver already parked** on an empty channel when its last sender crashes is woken as a deadlock rather
  than with the producer's reason.
- **`strings` exposes `fold_upper` / `fold_lower`** where the byte-level pair would naturally be named
  `to_upper` / `to_lower`. This compiler flattens every module into one namespace, and `strings` composes over
  `ascii`, which declares those names. It is a workaround, named as one, and the flattening will meet any user
  module that shares a name with the stdlib.

## What this release does not promise

There is no compatibility promise yet. 0.1.0 is the first number, not a stability claim: the surface will move,
and a `[not yet]` becoming built is the ordinary way it will move. What **is** promised is the standing contract
— a form is implemented or refused by name — and that the specification says which is which.
