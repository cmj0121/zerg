# Zerg 0.2.0 — release notes

The second release, and the first with something to compare itself against. 0.1.0's sentence was _Zerg
stopped being a Go program that reads Zerg and became a Zerg program that reads Zerg_. This one has two
subjects and it is worth naming both rather than pretending to one:

- **the compiler and its specification stop disagreeing** — and where they still do, it is because this
  release went looking, not because the last one left it there
- **the file becomes the unit** — the one narrowing this release spends its breaking window on

The short version is [`CHANGELOG.md`](../../CHANGELOG.md) at the repository root. This is the long one.

## How to read this

**Which compiler.** `make` builds two. `zerg0` is a Go-hosted seed whose only job is building the compiler;
`zerg` is that compiler, written in Zerg, and the one a build puts in `bin/`. **Every claim below is about
`zerg`.** The seed's narrower subset is its own contract, in
[`src/bootstrap/README.md`](../../src/bootstrap/README.md), and a reader writing Zerg never meets it.

**The standing contract is unchanged.** A form is either lowered correctly or refused **by name** at compile
time. Never a crash, never a silently wrong answer, and never an error reported by `cc` or the linker against
generated code nobody wrote.

**What this release adds to that contract is that the refusal has to be TRUE.** A code's range says which
question it answers, and `E9xxx` says _the language has this form and this compiler has not built it_. A
refusal that says that about a program the language does not have is a wrong answer with a correct exit
status, and 0.1.0 shipped a number of them.

## Half one — the specification stops disagreeing

**`[deviation]` is zero.** 0.1.0's specification named the places it was wrong; a reader who believed the
document was wrong about their program, and a document wrong in a known way is worse than a silent one
because it was trusted first. Every marker closed three ways and no others — the compiler was fixed, the spec
moved, or the requirement became a **door** with a threshold — and then the tree was searched for the ones
nobody had written down. (0.3.0 disposed of the doors: each is a position in the chapter that owns the
question, or an `[implementation-defined]` where a reader meets it.)

**The last one was the mangling.** Visibility is the file's, and it is checked as the tables say. What did
not follow was the C symbol: two modules could not each declare `pub fn helper`, because the symbols they
lower to are one flat space. The tag that separates two PRIVATE names — the module's position in a sorted
list of the program's modules — was simply not given to a public one.

**Every marker names its rule.** A `[not yet]` that quotes no code is a claim nothing holds: it cannot be
checked, and it cannot go stale loudly. Each one now quotes a code the compiler still raises, or names the
ticket for a rule that does not exist yet — and a gate holds the pair together, so a form that starts being
BUILT turns the board red rather than sitting on a list nobody re-reads.

**The markers went UP, and that is the criterion working.** Measuring a chapter against the compiler finds
gaps, and a release that is allowed to ship a new `[not yet]` unfixed is a release whose standard does not
reward silence. What may not survive is a marker that is _wrong_.

## Half two — the file is the unit

**Visibility and imports are the file's.** `pub` is checked against the file that declared the name, with a
place. A folder is a module by holding `mod.zg`. A project's own modules are spelled `./`, and a bare name
belongs to the standard library — four path prefixes, four roots.

**A module is what an import RESOLVED to**, not how it was spelled, so one directory reached two ways is one
module and not two. Files of one module do not share a namespace: a sibling's name is reached by importing
it, which is what lets two files of one module name each other mutually where two modules may not.

**A public name is not program-global.** The qualified call is what chooses: `a.helper()` names the module
out loud, so the row read for visibility and the symbol emitted are the namespace's. Every call site used to
ask for the caller's module, which is right for a private name — a bare call always means the caller's own —
and is the reason a public collision could not be told apart.

## Diagnostics

**Every refusal carries a code and a place.** 0.1.0 closed the place for checked rules; this release closed
it for the rest.

**A code's range names the stage that reports it.** Sixty-odd numbers moved to the range that answers their
question. The ones that stayed in `E9xxx` are the forms the language has and this compiler has not built —
which is what that range is for, and what it now means without exception.

**The measurement that says so.** `test-data/counterexamples` is 132 programs GRAMMAR does not derive. Being
told one of them is valid Zerg awaiting implementation is a contradiction, and it was being made **24 times**
at the start of the final pass. It is made **zero** times now, and a gate clause holds it there.

## Tooling

An **ignore file**, and the first pattern matcher this toolchain has. `fmt`, `lint` and `desugar` take
**files**, not directories. `zerg test` no longer follows a symlink into itself. An install stays in its
prefix, and the Homebrew formula reaches the platform the tarballs do not.

## The board

**Forty-seven gates became fifty-two**, and the four additions are all the same idea: hold a claim to
something that can fail.

- **`behaviour`** — every GRAMMAR production either runs a whole program whose output is diffed, or is
  refused by name with a code. 175 of 175.
- **`deviation-check`** — the 0.2.0 criterion as a gate rather than a promise.
- **`marker-codes`** — every `[not yet]` quotes a live code or names a ticket.
- **`chapter-codes`** — every unbuilt-form code is named in a chapter a reader can find.
- **`method-gaps`** — a method name the compiler calls unbuilt is a name a chapter promises.

**Two gates were passing without checking anything**, and one line each would have said so. A gate that
prints a count asserts nothing: break the pattern it reads with and it reports success for clauses that ran
zero times. Neither took a floor — the criterion is that the count reaches zero — so the READERS are held to
a fixture the gate carries, and each was proved red by breaking the reader it holds.

## What is not built

Eighteen specified features are refused by name, over twenty-five productions. Each is a sentence the
compiler will say to you, and each quotes the code it says it with.

| group            | features                                                                      |
| ---------------- | ----------------------------------------------------------------------------- |
| pattern matching | struct, list, tuple, or- and as-patterns, and a struct pattern's field target |
| f-strings        | the format spec, the conversion, the self-documenting `=`                     |
| command literals | `` `…` `` and its interpolating form                                          |
| types            | `[T; N]`, the raw pointer built-ins, `mut &` inside a `fn` type               |
| declarations     | a `spec` member with a body, an `impl`'s associated value                     |
| other            | `asm(…)`, and `unsafe { … }` as an expression                                 |

## What a careful reader still cannot discover alone

**Counterexample coverage is a floor, not a proof.** 120 of 175 productions have a program that is a
near-miss of them; the other 55 carry a machine-checked reason why they have none. There is no mechanical way
to know a production has run out of near-misses, so the number is a floor on the work and never a claim about
the grammar — the gate prints it that way on purpose.

**The seed is narrower than the compiler**, deliberately, and 76 corpus programs it cannot build are each
accounted for by name. Where the two disagree about a program that IS in the seed's subset, the board fails.

**`--emit lib` writes objects and no header**, and nothing reports which `pub` declarations a header would
carry. The FFI chapter is a design rather than a description; both its edges are refused by name.
