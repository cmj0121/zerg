# Zerg 型別系統（Type System）

每一條型別規則所推導自的概念——一個型別**是什麼**,以及一個型別**如何被決定**。屬於
[語言參考](../language.zh-TW.md) 的一部分。亦有 [English](type-system.md) 版本。

[型別](types.zh-TW.md) 放的是形式與規則;本章只放它們所懸掛的概念。

## 你需要記住的

1. 數字、`[]`、`{:}`、`nil`,以及沒寫型別的 closure 參數,會**貼合它所在的槽**。
2. 其他東西必須**完全相符**——跨型別是一步**寫出來**的轉換,`T(x)`
   ([型別轉換](types.zh-TW.md#into--一個普通的轉換-spec))。
3. 沒有槽的時候,造一個:型別寫在**左邊**——`xs: list[byte] = []`。

本章其餘的部分,是把這三句話說精確。

## 一個型別是什麼

三條**公理**（axioms)——它們定義字彙的意思。

| 概念                          | 一句話                                                              |
| ----------------------------- | ------------------------------------------------------------------- |
| **identity is name and args** | 宣告的型別是它的名字加型別引數；沒有名字的形式則是它的組成          |
| **a conversion rebuilds**     | 跨型別是建出一個新值；沒有東西能把一個型別的儲存當成另一個來看      |
| **a type comes with nothing** | 沒有 `Object`、沒有 `==`、沒有排序,直到 `derive` 或某個 `impl` 給它 |

`struct`、`enum`、`spec`、`type X = Y` 就是它的**名字**：形狀相同的兩個是兩個型別。泛型是它的名字**加上**
引數——`Result[int]` 在哪裡寫都是 `Result[int]`。沒有名字的形式——tuple、`chan[T]`、`fn` 型別、陣列、
`T?`——是它的**組成**：寫法相同的兩個是同一個型別;而 carrier 就是這一列底下的普通型別,不是 null 或例外的
另一種寫法。

## 一個型別如何被決定

一個 **position**——備忘錄裡的「槽」——是一個運算式對它周圍的構造而言是什麼:有標註繫結的右側、一個引數、
一個分支、一個容器元素。它是結構性的,不是語法性的——`(e)` 和 `e` 是同一個 position——窮盡清單在
[型別](types.zh-TW.md#有型別的位置typed-positions)。

| 概念                               | 一句話                                                          |
| ---------------------------------- | --------------------------------------------------------------- |
| **a form may have no type**        | 它拿它的 position 要的那個,並在它被寫下的地方檢查               |
| **a value never re-types itself**  | 轉換是寫出來的；沒有東西會自己轉換                              |
| **one position, one type**         | 共用一個 position 的運算式收斂成一個型別;原始碼順序永遠不是輸入 |
| **parts decide, positions demand** | 型別由組成往上決定；要求往下傳到本身沒有型別的東西              |
| **inference is local**             | 型別在它被寫下的地方定案；之後任何用法都不會改寫它              |
| **ambiguity is an error**          | 沒有唯一答案、也沒有宣告的預設,就是拒絕,絕不是猜                |

五條註記把規則接到語言上:

- **五種無型別的形式**——數值 literal（無約束時用預設,`int` 或 `float`,`GRAMMAR#literal`)、空的 `[]`、空的
  `{:}`、`nil`,以及沒寫型別的 closure 參數（`GRAMMAR#closure-param`)。其他東西都自帶型別。之所以數它,是因為
  這個數目本身就是主張:不在這張清單上的形式都自帶型別,而第六種必須先被加進這裡,底下任何一條規則才可能對它成立。
- **要求停在組成前。** 它只往下穿過那五種形式——絕不跨進組成已定案的運算式——而運算子鏈成對相遇,每次相遇
  是它自己的 position。而一個**每個組成都無型別**的運算式,什麼也沒定案,所以要求會穿過它:
  `x: byte = 100 + 100` 是 byte 算術,`x: float = 1 / 2` 是 `0.5`——literal 在運算子執行**之前**就取得了
  型別。放不進去的組成在它被寫下的地方被拒(`x: byte = 300 - 100` 裡的 `300`),而之後的算術就是目標型別
  自己的算術,含溢位在內。
- **Carrier 把 position 往內移。** `x: int? = e` 把 `e` 放在 `int` 之前——position 可以這樣把值**包起來**
  (carrier、spec 的盒子);絕不改值的型別。
- **Spec-typed 的 position 是建構。** spec 的盒子建在值的外面,單向——沒有東西轉得回來,剩下唯一能問的是
  `is`([Specs 與泛型](specs.zh-TW.md))。
- **呼叫自己解自己的參數。** `T` 來自引數,絕不是答案落地的位置:`x: float = id(5)` 把 `T` 解成 `int`
  (literal 在 `x: T` 上用預設),而那個 `int` 答案接著在繫結處被拒絕——寫 `float(id(5))`。要求既不解 `T`、
  也不替答案轉換:**inference is local**,兩次。

> **[not yet]** 有兩條註記跑在編譯器前面:沒寫型別的 closure 參數、以及把 spec 用作型別,都會被指名拒絕
> ——spec position 之中,建好的是錯誤層(`Result[T]` 裡的 `Err`)。
>
> 本章其餘的部分,兩個編譯器都守住了,而且都說得出位置:會轉換的 position、兩個型別相遇的運算元,以及沒有
> position 可取型別的無型別形式,三者都是帶 place 的拒絕。

## 為什麼是這九個

公理定義字彙的意思;規則說什麼可以發生;每個推論都是某條規則往前走一步:

- **parts decide, positions demand**——已定型的值不可被改型(規則二),所以要求只能作用在沒有型別的東西上
  (規則一)。
- **inference is local**——一個會改寫型別的較晚用法,就是值在替自己改型。
- **ambiguity is an error**——沒有要求、也沒有宣告的預設時,任何選擇都需要規則沒有給的輸入。

這就是本章的檢驗標準——一個既不是公理、不是規則、也不是某條規則之推論的概念,不屬於這裡;而一條需要第四條
才站得住的規則,是一條還沒被理解的規則。
